01 — 地震波

为什么总能「先见闪电，后闻雷声」？

因为光跑得比声音快。地震也藏着同样的秘密：两类波同时从震源出发，快的先到，慢的才是破坏者——预警，就是利用这个时间差。

地震发生的瞬间，会同时放出两类波：跑得快的 P 波（纵波 · 压缩波）几乎无害，跑得慢的 S 波（横波 · 剪切波）才是让建筑摇晃、致人伤亡的元凶。就像闪电先到、雷声后到——P 波先到，S 波后到。

03 — 烈度公式

同一次地震，为什么有人被晃醒，有人毫无感觉？

因为离震中的距离不同。地震哨兵算的不是「震级」（地震本身多大），而是你这里有多晃（本地烈度），再决定要不要打扰你。

同样一次 6.5 级地震：震中 20 公里外，烈度约 6.9 度，吊灯猛晃、书架倾倒；500 公里外，烈度只剩约 2.5 度，多数人毫无感觉。地震哨兵采用 GB 18306-2015《中国地震动参数区划图》第六代六分区短轴衰减模型，按震中坐标自动选用所在分区系数，结合震级、震中距与深度估算你所在地的烈度，低于阈值只进通知栏，不打扰你。

I ≈ 2.941 + 1.363·M − 1.494·ln(R + 7)
M震级 R你到震中的距离 (km) I你所在地的烈度

为什么不用震级直接告警

震级只描述地震本身有多大，但对你有没有危险，取决于你离它多远。按本地烈度触发，才能做到「远处大震不骚扰、近处小震及时报」。

05 — 核心引擎 · EewFusion

EewFusion：地震哨兵的心脏

如果说数据源是眼睛、手机是嘴巴，EewFusion 就是大脑。它借鉴集成学习（Ensemble Learning）思想，把每一条链路当作一位独立「专家」，在 1.0–1.5 秒动态融合窗口内收集多源报文、加权融合、震级校准与趋势融合、相互印证——单源的抖动、造假或误报，都无法单独左右最终结论。没有它，「多源预警」不过是把几个单源转发器简单并列；正是它，把「看得见」变成了「判断得准」。

五路实时源并行 → 1.0–1.5s 动态窗口加权融合、震级校准与趋势融合 → 坐标选优 + 置信度闸门 → 统一分级告警。单源报告会被标记 isPreliminary，无法单独触发红色警报。

集成学习框架

五路实时源各为一位独立「专家」，结论由集体交叉验证得出，而非某一源独裁。

1.0–1.5s 动态融合窗

多源在线时自动缩短、单源时延长，短到不拖慢预警、长到完成多源交叉验证。

加权中位数 + 震级校准

抗异常值设计，并按「源 × 震级桶」预训练修正，偏差钳制 ±0.5，从源头压制误报。

坐标选优 + 死区防抖

取权重最高源的原始坐标（非平均），带坐标死区防抖，天然抗单源定位抖动。

初报 / 终报双轨

置信 = 源数×0.6 + 一致性×0.4；单源报告标记 isPreliminary，不触发红色；修正 >±0.4 强制推送。

工程级稳健

震级校准 · 趋势融合 · 坐标防抖 · 事件版本隔离 · 状态 TTL 30min 淘汰 · 10min 跨源去重。

为什么这是我们的护城河

单源转发器，谁都能接；把五路实时源收敛成一个可信结论，才需要一套自研的融合决策逻辑。EewFusion 以Apache-2.0 协议开源（UI / 解析 / 烈度衰减 / 告警 / 历史 / 证书固定 / 构建），其核心融合与 FusionCalibration 以专有协议分发、不随仓库公开——这正是产品不可替代的核心。

06 — 可靠性与安全

可靠性工程与安全架构

预警系统最坏的情况不是「没收到」，而是「收到假的」或「撑久了崩」。地震哨兵在可靠性工程与安全架构两端都做了专门设计，让它在长时间后台运行与不可信网络下依然可信。

可靠性工程

  • 状态 TTL 淘汰：按事件版本隔离，30 分钟超时状态自动回收，杜绝内存泄漏（v1.3.2 修复）。
  • 跨源去重：10 分钟窗口内同一地震只弹一次，不重复打扰。
  • 事件版本隔离：每次地震独立成「版本」，初报与终报互不污染。
  • 超时强制输出：融合窗口到点必出结论，绝不无限等待。
  • 坐标防抖 / 死区：低于阈值的位移不更新坐标，抑制抖动与跳变。

安全架构

  • 证书固定（Cert Pinning）：对 6 个关键域名固定证书指纹，中间人替换证书即断连。
  • 抗伪造：单源报文须通过加权中位数 + 置信度闸门，伪造初报无法单独触发红色。
  • 组件暴露面最小化：Receiver / Service 仅做最小权限声明，敏感能力不对外暴露。
  • 密钥管理：第三方令牌不再内置，改由用户自行填写，密钥不随仓库分发。
  • 版本一致性：修正量 >±0.4 强制推送新版本，避免旧结论滞留。
07 — 预警盲区

离闪电太近，雷声和闪电几乎同时到

预警依赖「地震已经发生、但破坏波还没到」这件事。越靠近震中，S 波越快抵达，留给预警的时间越短——近到一定程度，预警根本来不及发出。这是所有地震预警系统共有的物理局限。

  • 近场盲区

    离闪电太近，雷声与闪电几乎同时到。同理，震中附近 S 波与测定同步到达，预警来不及发出。

  • 预警有效区

    有一定距离，既有足够时间测定、又能在 S 波前送达，是预警真正发挥作用的地方。

  • 远场衰减区

    距离更远，震动已明显衰减，常只进通知栏记录，不再打扰你。

没收到警报 ≠ 没有地震

即使预警因盲区、网络或设备原因没送达，只要感受到震动，请立即按避险本能行动。预警是参考，不是保险。

08 — 触发决策

一次预警，怎么决定要不要叫醒你？

从一段原始报文到一次全屏告警，中间只有几个确定性的判断，没有任何「猜」。下面这条流程，就是每次预警都会走的逻辑。

收到预警报文来自任一数据源，含震中、震级、深度、发震时刻
估算本地烈度 I用震级 M、震中距 R、深度 D，结合你的位置反推
本地烈度 I ≥ 阈值 且 多源已交叉验证？阈值默认 2°（推荐），可设为 3° / 4°；单源初报标记 isPreliminary 禁止触发红色；启动后冷静期防误报
是 → 按等级全屏倒计时Ⅰ红≥7° / Ⅱ橙5-6° / Ⅲ黄3-4° / Ⅳ蓝<3°，锁屏之上、自动亮屏、真实语音 + 震动同步
否 → 仅通知栏 / 历史不打断你，安静记录这次地震

扫描线自上而下掠过，节点依次点亮——每次预警都严格走这套确定性判断，不做任何「猜」
